# `j2` — Jinja2 templates

| Function | Description |
| --- | --- |
| `j2.template(template_text, data)` | Render a template string with default options. Returns the rendered text. |
| `j2.engine()` | Create a configurable engine handle with chainable `with_*` setters, then render via `:template(...)`. |

```lua
local text = j2.template(
  "Hello {{ name }}!{% for i in items %} {{ i }}{% endfor %}",
  {name = "world", items = {1, 2, 3}}
)
fs.write("out.txt", text)
```

## Conventions

Backed by [minijinja](https://docs.rs/minijinja) (a Rust Jinja2
implementation), built with the `custom_syntax` and `loader` features. The
core Jinja dialect — variables (`{{ }}`), blocks (`{% %}`), comments
(`{# #}`), `if`/`elif`/`else`, `for` loops, macros, filters (`|`), tests
(`is`), and expression operators — is available. `{% include %}` and
`{% extends %}` are available only once an include root is configured
(below); nothing else in the dialect depends on the filesystem.

`data` (the template context) accepts any Luau value — tables, strings,
numbers, booleans, `nil` — converted through the same JSON-like value
model `json`/`yaml` use (a Lua table becomes a Jinja mapping or sequence
depending on its keys).

**Includes follow the `fs` capability model**, not a setting of their
own: an include is a file read, so how far one can reach mirrors what
`fs` exposes to the running binary.

- `iq`/`ied` — includes resolve under `:with_include_root(path)` like any
  other `fs` path: relative to the VFS root, confined to it. A leading
  `/` means the VFS root.
- `ito`/`irun` — `path` is an ordinary host path (cwd-relative or
  absolute); includes are then confined to *that* directory specifically
  — there being no wider root to fall back on. `{% include
  "../../etc/passwd" %}` cannot escape the named directory.
- No `fs` at all (e.g. `iq` without `-f`) — `:with_include_root` raises;
  `j2.template`/`:template` still work, since rendering a template
  *string* touches no filesystem either way.

In every case `..` traversal and symlink escapes past the boundary are
rejected. Includes read current disk state, like `fs.read` — never
`ied`'s buffered, uncommitted writes.

## `j2.template`

Render `template_text` with `data` as the context, using minijinja's
defaults (lenient undefined, no whitespace trimming, trailing newline
stripped, no custom delimiters, includes disabled).

**Signature**

```lua
j2.template(template_text: string, data: any) -> string
```

**Parameters**

- `template_text` — the Jinja2 template source.
- `data` — the render context; any Luau value.

**Returns**

The rendered string.

**Errors**

Raises on a template syntax error or a render-time error (e.g. an
operation minijinja rejects, such as calling a method on an undefined
value under `"strict"` — though `j2.template` always uses the lenient
default). `{% include %}`/`{% extends %}` always fail here: default
options set no include root, so any include tag raises rather than
loading anything.

**Example**

```lua
local text = j2.template("{% for x in items %}{{ x }}\n{% endfor %}", {items = {"a", "b"}})
-- text == "a\nb\n"
```

## `j2.engine`

Create a configurable engine handle for rendering with non-default
options.

**Signature**

```lua
j2.engine() -> J2Engine
```

**Returns**

A `J2Engine` handle. Cheap to clone/alias: every reference shares the
same underlying options, so chained calls and copies observe the same
state.

**Example**

```lua
local e = j2.engine():with_undefined("strict")
```

## `J2Engine:with_undefined`

Set how undefined variables behave during render.

**Signature**

```lua
engine:with_undefined(mode: string) -> J2Engine
```

**Parameters**

- `mode` — one of `"lenient"` (default; undefined renders as empty and
  most operations on it are tolerated), `"chainable"` (undefined
  propagates through attribute/item access without erroring until
  actually printed or used), `"strict"` (any use of an undefined value
  raises).

**Returns**

The same handle (for chaining).

**Errors**

Raises immediately if `mode` is not one of the three strings above.

**Example**

```lua
local e = j2.engine():with_undefined("strict")
local ok, err = pcall(function() return e:template("{{ missing }}", {}) end)
-- ok == false
```

## `J2Engine:with_trim_blocks`

Strip the first newline after a block tag (`{% ... %}`).

**Signature**

```lua
engine:with_trim_blocks(yes: boolean) -> J2Engine
```

**Parameters**

- `yes` — enable (`true`) or disable (`false`, the default) trimming.

**Returns**

The same handle.

**Example**

```lua
local e = j2.engine():with_trim_blocks(true)
```

## `J2Engine:with_lstrip_blocks`

Strip leading whitespace on a line before a block tag.

**Signature**

```lua
engine:with_lstrip_blocks(yes: boolean) -> J2Engine
```

**Parameters**

- `yes` — enable (`true`) or disable (`false`, the default) stripping.

**Returns**

The same handle.

**Example**

```lua
local e = j2.engine():with_lstrip_blocks(true)
```

## `J2Engine:with_keep_trailing_newline`

Control whether a single trailing newline in the template source survives
into the output.

**Signature**

```lua
engine:with_keep_trailing_newline(yes: boolean) -> J2Engine
```

**Parameters**

- `yes` — keep it (`true`) or strip it (`false`, the default —
  minijinja's normal Jinja2-compatible behavior).

**Returns**

The same handle.

**Example**

```lua
local e = j2.engine():with_keep_trailing_newline(true)
```

## `J2Engine:with_syntax`

Replace the default `{{ }}` / `{% %}` / `{# #}` delimiters with custom
ones.

**Signature**

```lua
engine:with_syntax(
  block_start: string, block_end: string,
  var_start: string, var_end: string,
  comment_start: string, comment_end: string
) -> J2Engine
```

**Parameters**

- `block_start`, `block_end` — delimiters replacing `{%`/`%}`.
- `var_start`, `var_end` — delimiters replacing `{{`/`}}`.
- `comment_start`, `comment_end` — delimiters replacing `{#`/`#}`.

**Returns**

The same handle.

**Errors**

Raises if minijinja rejects the delimiter set (e.g. conflicting or
invalid delimiters).

**Example**

```lua
local e = j2.engine():with_syntax("<%", "%>", "<<", ">>", "<#", "#>")
local text = e:template("<< name >>", {name = "x"})
-- text == "x"
```

## `J2Engine:with_include_root`

Enable `{% include %}`/`{% extends %}` by naming the directory templates
are loaded from.

**Signature**

```lua
engine:with_include_root(path: string) -> J2Engine
```

**Parameters**

- `path` — the include directory. Under `iq`/`ied` this is a VFS path
  (a leading `/` means the VFS root); under `ito`/`irun` it is an
  ordinary cwd-relative or absolute host path, resolved immediately
  against the current working directory.

**Returns**

The same handle.

**Errors**

Raises if the binary exposes no filesystem at all (there is then no
directory to resolve `path` against). Does not itself check that the
directory exists — a missing or escaping include is reported later, at
`:template()` time, per include tag.

**Example**

```lua
local e = j2.engine():with_include_root("templates")
local text = e:template('{% include "layout.txt" %}', {body = "Hi"})
```

## `J2Engine:template`

Render a template string using the handle's configured options.

**Signature**

```lua
engine:template(template_text: string, data: any) -> string
```

**Parameters**

- `template_text` — the Jinja2 template source.
- `data` — the render context; any Luau value.

**Returns**

The rendered string.

**Errors**

- Template syntax error, or a render-time error under the configured
  `with_undefined` mode.
- An `{% include %}`/`{% extends %}` naming a path that escapes the
  include root (via `..` or a symlink) — rejected the same way under
  both filesystem shapes.
- An include naming a file that fails to read for a reason other than
  "not found" (missing simply resolves as no template).
- Custom syntax that minijinja rejects (surfaces at `:with_syntax`, not
  here).

**Example**

```lua
local text = j2.engine()
  :with_undefined("strict")
  :with_include_root("templates")
  :template('{% include "layout.txt" %}', {body = "Hi"})
```
