# `j2` — Jinja2 templates

| Function | Effect |
| --- | --- |
| `j2.template(template_text, data[, opts])` | Render a template string. Returns the rendered text. |
| `j2.engine()` | Create a configurable engine handle with chainable `with_*` setters, then render via `:template(...)` / `:render(...)`. |

## Example

```lua
local text = j2.template(
  "Hello {{ name }}!{% for i in items %} {{ i }}{% endfor %}",
  {name = "world", items = {1, 2, 3}}
)
fs.write("out.txt", text)
```

## Conventions

Backed by [minijinja](https://docs.rs/minijinja) (a Rust Jinja2
implementation) plus `minijinja-contrib`'s Python compatibility. The core
Jinja dialect — variables (`{{ }}`), blocks (`{% %}`), comments
(`{# #}`), `if`/`elif`/`else`, `for` loops with `{% break %}`/`{% continue %}`,
macros, filters (`|`), tests (`is`), and expression operators — is
available. `{% include %}`, `{% extends %}` and `engine:render` are
available only once an include root is configured (below); nothing else in
the dialect depends on the filesystem.

- **Python-style methods** work: `d.items()`, `d.keys()`, `s.upper()`,
  `s.split(",")`, ….
- **Extra filters**: `tojson`, `urlencode`, and these Ansible-flavoured
  ones — `to_yaml`, `b64encode`, `b64decode`, `regex_replace(pattern,
  repl)` (Python-style `\1` or `$1` references), `basename`, `dirname`,
  `combine(...)` (merge mappings, later wins), `mandatory([message])`
  (raises on an undefined value), `quote` (shell-quote). All are pure.
- **Booleans print Python-style** (`True`/`False`).
- **No auto-escaping by default.** Output is text. minijinja would otherwise
  HTML-escape an included `*.html`/`*.xml` by its name; opt in with
  `:with_autoescape("html")`.

`data` (the template context) must be a **table** or `nil` (an empty
context). It is converted through the same JSON-like value model
`json`/`yaml` use; an empty table becomes an (empty) mapping, never a
sequence. Anything else, or a table holding a value that cannot be
represented (a function), raises `j2.template: data: …`.

**Includes follow the `fs` capability model**, not a setting of their
own: an include is a file read, so how far one can reach mirrors what
`fs` exposes to the running binary.

`:with_include_root(path)` takes an ordinary host path (cwd-relative or
absolute); includes are confined to *that* directory.

In `ied`, `path` resolves like any other `fs` path: relative to the work
directory (a leading `/` raises), and includes are confined to the include root
and the work directory
([reproducibility](../binaries/ied.md#reproducibility)).

In every case `..` traversal and symlink escapes past the include root are
rejected (both shapes behave identically; only a non-existent target falls
through to the "not found" error). A **missing include raises** `template
not found` unless the tag says `{% include "x" ignore missing %}`. Includes
read current disk state, like `fs.read` — never `ied`'s buffered,
uncommitted writes.

**Errors** carry the function name, minijinja's source context (template
line and excerpt) and any cause chain, e.g. `j2.template: … caused by: …`.

**Builder and terminal.** `j2.engine()` returns a `J2Engine`; every
`:with_*` setter mutates that shared handle in place and returns the same
handle, so `local a = e:with_undefined("strict")` aliases `e`. A bad
argument (an unknown mode, a malformed delimiter set) raises at the setter;
include and render errors surface at `:template()`/`:render()`, the
terminals. Neither terminal is async.

**Performance.** An engine builds its environment once and reuses it until
a setter changes it.

## `j2.template`

Render `template_text` with `data` as the context.

**Signature:** `j2.template(template_text: string, data: table?, opts: table?) -> string`

**Parameters:**

- `template_text` — the Jinja2 template source.
- `data` — the render context: a table, or `nil`.
- `opts` — optional table: `undefined` (see `with_undefined`),
  `autoescape` (see `with_autoescape`), and the booleans `trim_blocks`,
  `lstrip_blocks`, `keep_trailing_newline`. An unknown key raises.

**Returns:**

The rendered string.

**Errors:**

Raises on a non-string template, a bad `data`/`opts`, a template syntax
error, or a render-time error. `{% include %}`/`{% extends %}` always fail
here: no include root is set, so any include tag raises.

```lua
local text = j2.template("{% for x in items %}{{ x }}\n{% endfor %}", {items = {"a", "b"}})
-- text == "a\nb\n"
j2.template("{{ v }}", {}, {undefined = "strict"})  -- raises
```

## `j2.engine`

Create a configurable engine handle for rendering with non-default
options.

**Signature:** `j2.engine() -> J2Engine`

**Returns:**

A `J2Engine` handle. Cheap to clone/alias: every reference shares the
same underlying options, so chained calls and copies observe the same
state.

**Methods:** `with_undefined` · `with_trim_blocks` · `with_lstrip_blocks` ·
`with_keep_trailing_newline` · `with_autoescape` · `with_syntax` ·
`with_include_root` · `with_filter` · `with_test` · `with_global` ·
`template` · `render`

```lua
local e = j2.engine():with_undefined("strict")
```

## `J2Engine:with_undefined`

Set how undefined variables behave during render.

**Signature:** `engine:with_undefined(mode: string) -> J2Engine`

**Parameters:**

- `mode` — one of `"lenient"` (default; undefined renders as empty and
  most operations on it are tolerated), `"chainable"` (undefined
  propagates through attribute/item access without erroring until
  actually printed or used), `"semi_strict"` (like strict, but an undefined
  value is allowed in `if` conditions and `is defined` tests), `"strict"`
  (any use of an undefined value raises).

**Returns:**

The same handle (for chaining).

**Errors:**

Raises immediately if `mode` is not one of the four strings above.

```lua
local e = j2.engine():with_undefined("strict")
local ok, err = pcall(function() return e:template("{{ missing }}", {}) end)
-- ok == false
```

## `J2Engine:with_trim_blocks`

Strip the first newline after a block tag (`{% ... %}`).

**Signature:** `engine:with_trim_blocks(yes: boolean) -> J2Engine`

**Parameters:**

- `yes` — enable (`true`) or disable (`false`, the default) trimming.

**Returns:**

The same handle.

```lua
local e = j2.engine():with_trim_blocks(true)
```

## `J2Engine:with_lstrip_blocks`

Strip leading whitespace on a line before a block tag.

**Signature:** `engine:with_lstrip_blocks(yes: boolean) -> J2Engine`

**Parameters:**

- `yes` — enable (`true`) or disable (`false`, the default) stripping.

**Returns:**

The same handle.

```lua
local e = j2.engine():with_lstrip_blocks(true)
```

## `J2Engine:with_keep_trailing_newline`

Control whether a single trailing newline in the template source survives
into the output.

**Signature:** `engine:with_keep_trailing_newline(yes: boolean) -> J2Engine`

**Parameters:**

- `yes` — keep it (`true`) or strip it (`false`, the default —
  minijinja's normal Jinja2-compatible behavior).

**Returns:**

The same handle.

```lua
local e = j2.engine():with_keep_trailing_newline(true)
```

## `J2Engine:with_autoescape`

Choose what the output is escaped for.

**Signature:** `engine:with_autoescape(mode: string) -> J2Engine`

**Parameters:**

- `mode` — `"none"` (default), `"html"` (escape `& < > " '`), or `"json"`.
  Applies to every template, including includes whatever their name.

**Returns:**

The same handle.

**Errors:**

Raises immediately on an unknown mode.

```lua
j2.engine():with_autoescape("html"):template("{{ v }}", {v = "<b>"})  -- "&lt;b&gt;"
```

## `J2Engine:with_syntax`

Replace the default `{{ }}` / `{% %}` / `{# #}` delimiters with custom
ones.

**Signature:**

```lua
engine:with_syntax(
  block_start: string, block_end: string,
  var_start: string, var_end: string,
  comment_start: string, comment_end: string
) -> J2Engine
```

**Parameters:**

- `block_start`, `block_end` — delimiters replacing `{%`/`%}`.
- `var_start`, `var_end` — delimiters replacing `{{`/`}}`.
- `comment_start`, `comment_end` — delimiters replacing `{#`/`#}`.

**Returns:**

The same handle.

**Errors:**

Raises **at the setter** if minijinja rejects the delimiter set (empty or
conflicting delimiters).

```lua
local e = j2.engine():with_syntax("<%", "%>", "<<", ">>", "<#", "#>")
local text = e:template("<< name >>", {name = "x"})
-- text == "x"
```

## `J2Engine:with_include_root`

Enable `{% include %}`/`{% extends %}`/`:render` by naming the directory
templates are loaded from.

**Signature:** `engine:with_include_root(path: string) -> J2Engine`

**Parameters:**

- `path` — the include directory: an ordinary cwd-relative or absolute host path,
  resolved immediately against the current working directory. Under `ied`
  it is rooted at the work directory.

**Returns:**

The same handle.

**Errors:**

Raises if the binary exposes no filesystem at all (there is then no
directory to resolve `path` against), or (rooted) if `path` is absolute or
escapes the root. Does not itself check that the directory exists — a
missing or escaping include is reported later, at render time, per include
tag.

```lua
local e = j2.engine():with_include_root("templates")
local text = e:template('{% include "layout.txt" %}', {body = "Hi"})
```

## `J2Engine:with_filter` / `with_test` / `with_global`

Add a Luau function to the templates: a filter (`{{ x|name(args) }}`), a
test (`{% if x is name %}`), or a global (a value, or a function called as
`{{ name(args) }}`).

**Signature:**

```lua
engine:with_filter(name: string, fn: function) -> J2Engine
engine:with_test(name: string, fn: function) -> J2Engine
engine:with_global(name: string, value: any) -> J2Engine
```

**Parameters:**

- `name` — the name in templates.
- `fn` — called with the template values converted to Luau (the filtered
  value first, then the arguments); a filter/global returns the new value
  (`nil` becomes none), a test returns truthiness.
- `value` — any data value (converted like `data`), or a function.

**Returns:**

The same handle.

**Errors:**

`with_global` raises on a value that cannot be represented. An error inside
`fn` surfaces as a render error.

```lua
local e = j2.engine()
  :with_filter("shout", function(s, n) return s:upper() .. string.rep("!", n or 1) end)
  :with_global("site", "ito")
e:template("{{ 'hi'|shout(2) }} {{ site }}", {})   -- "HI!! ito"
```

## `J2Engine:template`

Render a template string using the handle's configured options.

**Signature:** `engine:template(template_text: string, data: table?) -> string`

**Parameters:**

- `template_text` — the Jinja2 template source.
- `data` — the render context: a table, or `nil`.

**Returns:**

The rendered string.

**Errors:**

- Template syntax error, or a render-time error under the configured
  `with_undefined` mode.
- An `{% include %}`/`{% extends %}` naming a path that escapes the
  include root (via `..` or a symlink), naming a missing template (unless
  `ignore missing`), or failing to read.

```lua
local text = j2.engine()
  :with_undefined("strict")
  :with_include_root("templates")
  :template('{% include "layout.txt" %}', {body = "Hi"})
```

## `J2Engine:render`

Render a template loaded from the include root by name.

**Signature:** `engine:render(name: string, data: table?) -> string`

**Parameters:**

- `name` — the template's path under the include root.
- `data` — the render context: a table, or `nil`.

**Returns:**

The rendered string.

**Errors:**

Raises if no include root is set, if the template is missing or escapes the
root, or on a syntax/render error.

```lua
local e = j2.engine():with_include_root("templates")
fs.write("out/site.conf", e:render("site.conf.j2", {host = "a.example"}))
```
